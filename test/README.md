# 协议回归测试

测试样本来自真实表计日志，并已固化为夹具，运行时不依赖原日志目录：

- DL/T 698.45 表计日志
- DL/T 645-2007 表计日志

每次修改 `645.js`、`698.js`、`ble.js` 或协议节点入口后，提交前必须执行：

```bash
npm test
```

命令只有在全部用例通过时才返回退出码 0，可直接作为 CI 或发布脚本的质量门禁。
GitHub Actions（`.github/workflows/test.yml`）在 push/PR 时自动执行，
矩阵覆盖 Node 16/18/20/22。

## 测试分层

回归套件由三个互相独立的文件组成，`npm test` 依次执行：

1. **协议夹具 + 日志类型样本**（`protocol-regression.js`，`npm run test:protocol`）
   - `meter-regression.json` 保留 698 可读的关键业务字段断言。
   - `meter-regression-698-samples.json` 为日志**按响应形态抽样**的样本（每形态首帧），
     附带可读的解码期望值（业务结果 + 统一格式 + 帧信息），校验 OAD 与响应形态。
   - `meter-regression-645.json` 保留可读的关键业务字段断言。
   - `meter-regression-645-samples.json` 为日志**按响应类型抽样**的样本（每类型首帧），
     附带可读的解码期望值，校验 DI，并强制检查 106 种响应类型、30 次正反向日冻结和
     12 月正反向结算冻结均完整覆盖。
   样本期望值初版由当前实现生成（语义上仍是快照）；人工核对业务数据后，
   可逐条将其改为业务确认值，升级为真正的验证数据。

2. **负例/健壮性**（`negative-regression.js`，`npm run test:negative`）
   固化"优雅失败契约"：任何畸形输入（空/截断/无起始符/非法 hex/奇数长度/超长/
   非字符串/坏校验和）都不得抛异常，且——
   - 645：失败时 `payload.ok === false` 并给出 `reason`（如 `empty`、`cs_fail`）；
   - 698：失败时设置 `msg.error` 且 `payload === null`（如 `FCS校验失败`）。

3. **往返**（`roundtrip-regression.js`，`npm run test:roundtrip`）
   编码出的帧必须能被解码器吃回去：645 还原通信地址（含小端反转）、DI 与控制码，
   含批量数组编码；698 通过帧结构与 FCS 校验，还原服务器地址与 OAD。

当前样本覆盖 DL/T 698.45 和 DL/T 645-2007 的地址读取、型号与常数、电能、瞬时量、
时钟与电池、状态字、冻结数据、事件次数、事件明细以及失败响应。日志中没有成功的 BLE
通信样本，因此 BLE 暂未伪造测试数据；取得真实成功日志后应按相同格式补充夹具。

645 的"上一次事件记录"类 DI（`03360001` 负荷开关误动作、`03370001` 电源异常、
`03110001` 掉电、`03300D01` 开盖明细）在两批日志中没有样本，对应解码用例使用按
`645.js` 解析器格式构造的**合成帧**（夹具中 `sourceLog` 标注为 `synthetic`）。
取得包含这些响应的真实日志后，应替换为真实帧并同步更新语料。

698 的 SET/ACTION/CONNECT-Response 在两批日志中同样没有样本（语料全部为
GET/SECURITY 响应），已用合成帧覆盖（HCS/FCS 由独立实现的 CRC-16/X-25 计算，
构造时曾与当时全量语料的 2528 帧内嵌校验值对拍通过）。698 编码侧的 `apduHex` 直通与
`customParameter.controlCode` 自定义控制码路径由往返回归用例守住。

## 已知覆盖缺口（2026-08-12 排查）

以下路径已确认存在、但当前无测试样本，按风险排序：

1. **BLE 协议（`ble.js`）**：无任何样本，需真实蓝牙通信日志或按手册构造合成帧。
2. **Node-RED 节点壳**（`zelecproto.js` / `zbatchproto.js` / `zeleble.js`）：
   消息流转层未测试（需最小 RED mock，见三期规划）。
3. **645 零样本专用解析器**（日志从未出现，建议合成帧补齐）：
   `01013003` 结算日冻结组合、`070000FF` 身份认证、`04000508` 密钥状态字、
   `040005FF`、`04000502`、`04000402`、`04000401`、`04000105`、`03300100`、
   `02030100`、`04000B01/02/03`（A/B/C 相电流）、`04040300` 屏显切换编码路径。
   低风险：B/C 相电压电流（`02010200/0300`、`02020200/0300`）与停电抄表电池
   （`02800009`）与已覆盖 DI 共用同一解析分支，代码路径已被走到。
4. **698 编码安全模式**：`plain`、`auto` 未测试（`none`、`plain_rn` 已覆盖）；
   `F3000500` 自动轮显响应特殊分支无样本。

## 重新生成类型样本

样本构建脚本（`scripts/build-*-type-samples.js`）仅保留在维护者本机，不入库；
夹具本身（`test/fixtures/*-samples.json`）随仓库提交。需要重建基线时，在本机执行：

```bash
node scripts/build-698-type-samples.js
node scripts/build-645-type-samples.js
npm test
```

只有确认新协议实现正确、并人工核对差异后，才能重建并提交新样本。
不能仅为了让失败测试变绿而更新样本期望值，否则会把协议回退固化为新基线。
